{# Per-tab subform for Settings → General. Issue #129 completion: previously the bulk `
` covered integrations + quality + general in one POST that always submitted all three tabs' fields together, which made HTMX migration awkward (one swap target couldn't represent a per-tab save) and let a Save click on one tab silently re-save the other two. Per-tab subforms isolate the fields to their tab, post to a dedicated endpoint (`/settings/general`), and HTMX-swap just the form region on save so the user gets a green toast + their inputs preserved without a full page render. Wrapper id="settings-general-region" is the swap target; the handler returns this same partial on the HTMX path so successful saves replace the form in place. The non-HTMX path returns the full SettingsTemplate and the browser does a normal redirect-style reload — progressive enhancement for users with JS off. hx-disinherit="hx-target hx-swap": htmx attributes inherit down the tree, so a plain link inside this form (the Recycle Bin and System → Backup hints) would otherwise be boosted INTO #settings-general-region and render the destination page nested inside Settings, sidebars overlapping. Disinheriting the two swap attributes lets those links boost to the body like every other link; the form's own hx-post still uses them. #}
