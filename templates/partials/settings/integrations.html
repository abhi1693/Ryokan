Download Client
Ryokan talks to one client at a time. Switching cancels any pending grabs queued against the previous client.
When set to Batches only, multi-file torrents open a modal where you can uncheck files (samples, NCOPs, extras) before the grab commits. Single-file torrents always skip the modal. Set to Never for 1.3.0-style one-click grabs.

rTorrent
XML-RPC endpoint URL. Ryokan appends /RPC2 automatically if the URL doesn't already end in it, matching Deluge/Transmission path handling. Common shapes: http://host:8081 for a local ruTorrent container, https://seedbox.example.com/rutorrent or https://seedbox.example.com for a seedbox.
HTTP Basic auth. Leave blank if the endpoint is unauthenticated (e.g. a same-host container on an internal network).
Stored in rtorrent's custom1 field (the ruTorrent label convention). Ryokan filters list_scoped by this value.
The local path where rtorrent's completed downloads are accessible to Ryokan. When rtorrent runs in Docker with a host volume mount, enter the host-side path. When rtorrent runs on a seedbox, enter the local mount point you reach it through (SSHFS/NFS/rclone). Leave blank only if Ryokan and rtorrent see the exact same paths. Note: many rtorrent.rc configs (including the linuxserver/rutorrent image's defaults) move completed torrents into a per-label subdirectory via event.download.finished hooks — e.g. /downloads/completed/ryokan/ rather than just /downloads/completed/. If your setup does this, include the label subdirectory in the path here (the scoping label you set above is typically the subdir name).
