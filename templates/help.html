Help

What is Ryokan?

Ryokan is a self-hosted anime PVR (Personal Video Recorder). It searches Nyaa for anime releases, scores them based on your preferences, and sends the best matches to qBittorrent for downloading. It uses AniList as its metadata source instead of TVDB, which means it understands how anime is actually released and catalogued.

Getting Started

After creating your account, head to Settings and configure your qBittorrent connection. Enter the URL, credentials, and a download category. Then go to Search to find releases on Nyaa. Results are scored automatically based on your configured preferences.

Search Tips

Use the uploader field to filter by a specific release group's Nyaa account. The category filter lets you narrow to English-translated or raw releases. "Trusted only" shows releases from verified Nyaa uploaders.

Try searching for batch releases by including "batch" in your query, e.g. "Jujutsu Kaisen batch 1080p".

Grabbing Releases

Click the Grab button next to any result to send it to qBittorrent. The torrent will be added with your configured category. Make sure qBittorrent is running and the connection is configured in Settings.

Forgot your password?

Ryokan stores the admin account in the same SQLite database as the rest of its config. There are two ways to recover access if you've forgotten your password. Both only wipe the users and sessions tables; your Jellyfin / qBittorrent credentials and other settings survive the reset.

Option 1: restart with the reset flag

On the machine running Ryokan:

  1. Create an empty sentinel file alongside the database: touch data/.reset-auth
  2. Restart Ryokan with the environment variable RYOKAN_RESET_AUTH=1 set, or with the --reset-auth CLI flag.
  3. Open Ryokan in your browser. You'll be redirected to the first-run setup page; create a new admin account.
  4. Remove the sentinel file: rm data/.reset-auth. Leaving it in place is harmless, but the env var alone won't wipe auth again without the sentinel.

The sentinel file is required so that a stuck-on RYOKAN_RESET_AUTH=1 in a docker-compose.yml can't accidentally wipe auth on every boot. Recovery is always a deliberate two-step action.

Option 2: sqlite3 recipe

If you can't easily restart Ryokan with a new environment variable (e.g. you're on a managed deployment), shut Ryokan down and run this once against the database:

sqlite3 data/ryokan.db "DELETE FROM users; DELETE FROM sessions;"

Then start Ryokan back up and create a new admin account through the first-run setup.
